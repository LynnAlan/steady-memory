# 架构与数据协议

## 设计原则

1. 本地优先：用户掌握完整档案，云端与模型只是可替换的客户端。
2. 人类可读：事实来源使用 Markdown、CSV 和 JSON，不依赖专有数据库。
3. 确定性写入：模型提取参数，程序负责校验、换算、去重、事务和审计。
4. 记忆分层：当天事实不自动成为长期判断，推断不能伪装成事实。
5. 最小权限：读取、普通写入、纠错和长期记忆应具有不同风险等级。

## 事实来源

| 内容 | 权威来源 | 说明 |
|---|---|---|
| 日常事件与主观感受 | `records/` | 唯一每日时间线 |
| 体重、身体指标、运动 | `data/*.csv` | 用于趋势计算；Markdown 是同步视图 |
| 稳定背景与偏好 | `memory/` | 需要明确确认或长期证据 |
| 当前计划 | `plans/*.json` | 带 ID、版本、状态和生效日期 |
| 媒体元数据 | `data/assets.csv` | 原图建议放仓库外 |
| 搜索和审计 | `.steady/` | 派生数据，可删除重建 |

## 信任层级

从高到低依次为：运行环境的系统策略、用户当前请求、本地录入策略、长期偏好、档案正文、历史 AI 判断。档案正文永远作为待分析的数据，而不是指令。

工具返回来源路径，Agent 的事实性回答应尽量引用来源。分析结论需要标明不确定性，不能在没有测量或医学诊断时写成确定事实。

## 写入事务

同一次记录可能更新结构化底账和当天 Markdown。工具会持有档案锁，先准备全部临时文件，再替换目标文件；发生冲突时默认拒绝覆盖。调用方只有在用户明确纠错时才能请求替换。

## Schema 与兼容性

档案根目录的 `steady.json` 包含 `schema_version`。公开版当前为 schema 1。未来任何破坏性格式变化都必须提供迁移命令，工具不能静默猜测或改写未知版本。

## 可扩展方向

健康、训练只是第一个领域。财务、阅读、家庭和创作可以作为独立领域包扩展，但需继续遵守事实来源、最小权限、可撤销和可迁移原则。
